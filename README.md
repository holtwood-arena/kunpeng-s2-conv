# 鲲鹏 HPC 挑战赛 S2 · CONV 算子优化

> Part of [holtwood-arena](https://github.com/holtwood-arena) · 比赛与 benchmark 归档

> 一个从朴素四重循环出发的 FP32 二维卷积优化项目：本地 x86 参考环境上相对基线
> **×17~21.6**（13.6 → 232~294 GFLOPS），实测 **12.1 FLOP/cycle**；鲲鹏平台尚未复测。
> 最大收益来自两次自我纠正：先发现编译器把向量化维度选错了（×2.5），
> 随后又发现**向量宽度本身就是主变量**（再 ×2.2~2.7）——后者推翻了前者的单因归因。
> 目标不是复现获奖作品，而是建立一条**可复现、可量化、可讲清**的性能优化证据链。

## 项目定位

| 项 | 内容 |
|---|---|
| 题目 | 鲲鹏高性能计算全球挑战赛 S2 · CONV 赛题（二维有效卷积，FP32） |
| 基线 | 官方 `conv2d.c`，30 行，四重循环 + `#pragma omp parallel for` |
| 评测 | 4 组官方用例，正确性容差 `1e-5`，按 GFLOPS 排名 |
| 本仓库目标 | 交付**一套性能优化方法论 + 完整实施记录**，用于面试；**不参与比赛**（S2 已于 2026-09-15 截止） |

## 核心主张

> 性能优化不是「改代码直到变快」，而是**在约束下做受控实验**：
> 建立可信测量 → 用证据定位瓶颈 → 用可证伪的假设驱动改动 → 用数据决定保留或回滚。

本项目刻意**不做**硬件特化（SME / 手写汇编）和尺寸硬编码：
前者无法在通用环境验证、讲不清原理就是负资产，后者是刷榜手段而非工程能力。

## 为什么做这道题

1. **baseline 是真朴素实现**（四重循环 + `memset` 后逐个 `+=`），实测已达 ×17~21.6
2. **完全可复现**：单文件 C + OpenMP，x86 上也能编译验证正确性
3. **指标干净**：GFLOPS，可换算峰值占比
4. **技术分层丰富**：算法选择 → 访存分块 → 指令级 SIMD → 线程调度
