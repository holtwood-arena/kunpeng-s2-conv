# 实验协议与记录规范

> 目的：让每一次改动都变成**可复核的证据**，而不是一段回忆。
> 规则很简单：**没有记录 = 没有发生**。

## 1. 一次实验的固定七步

```
1. 编号        → E01, E02, ...（永不复用编号）
2. 提假设      → 先写假设与证伪条件，再动手
3. 存基线      → 记录当前版本的 commit / 文件 SHA-256
4. 单变量改动  → 一次只改一个机制
5. 全量对拍    → 四案正确性，误差必须记录
6. 重复测量    → ≥3 次，报 min / median / max
7. 判决        → KEEP / REJECT / INCONCLUSIVE，并写代价
```

第 2 步在动手**之前**完成。这是防止事后编故事的唯一办法。

## 2. 记录模板

每次实验追加到 `docs/experiments/E##-<slug>.md`：

```markdown
# E## <标题>

- 日期：
- 上一版：<commit / 文件哈希>
- 本版：<commit / 文件哈希>
- 环境：<CPU 型号> / <核数> / <线程数> / <绑定方式> / <编译器版本>

## 假设

<当前实现中，某个具体机制导致了什么可观测的浪费>

## 预测

- GFLOPS：提升 ≥ X%
- 计数器/汇编：<期望看到什么>

## 证伪条件

- 若 <...>，则假设不成立

## 改动

<一句话说清改了什么，必要时贴伪代码；不要贴整段实现>

## 正确性

| 用例 | 结果 | 最大绝对误差 |
|---|---|---|
| 1 | PASS/FAIL | |
| 2 | | |
| 3 | | |
| 4 | | |

## 性能

| 用例 | 上一版 GFLOPS (min/med/max) | 本版 (min/med/max) | 中位数变化 |
|---|---:|---:|---:|
| 1 | | | |

## 判决

- 结果：KEEP / REJECT / INCONCLUSIVE
- 理由：
- **代价**：<复杂度 / 精度余量 / 可移植性 / 可维护性>

## 备注

<踩到的坑、意外发现、下次要注意的>
```

## 3. 噪声控制

测量不可信时，任何结论都是假的。三条要求：

1. **预热**：每次测量前至少跑 1 次不计入结果（首次触页、频率爬升、分支预测器冷启动）
2. **重复**：≥3 次，报 `min / median / max`。只看平均值会掩盖抖动
3. **同环境**：同一台机器、同一线程数、同一次登录会话内完成一组 A/B

判定阈：

- 抖动（max-min）/ median < 5% → 数据可用
- 抖动 ≥ 5% → 先修测量，不改代码
- 改动收益 < 抖动 → 判 `INCONCLUSIVE`，不要写成「有提升」

## 4. 环境标注规范

每个数据点必须能回答「在哪测的」。至少记录：

```
platform   : LOCAL_REFERENCE | KUNPENG_920F
cpu        : <型号>
cores      : <物理核数> / <逻辑核数>
omp_threads: <值>
binding    : <numactl / taskset 参数，或 none>
compiler   : <gcc/clang 版本>
flags      : <关键编译选项>
```

**强制规则**：`platform=LOCAL_REFERENCE` 的数据，**不得**在任何文档、README、简历、面试中表述为鲲鹏平台结果。

## 5. 判定规则

| 判决 | 条件 | 后续动作 |
|---|---|---|
| `KEEP` | 四案 PASS，误差未恶化，收益 > 2× 抖动 | 进入下一实验 |
| `REJECT` | 四案 PASS，但收益 ≤ 抖动，或明显变慢 | 回滚，保留记录 |
| `ROLLBACK_ON_TARGET` | 本地 PASS，但目标平台精度/性能不达标 | 保留分支，默认关闭 |
| `INCONCLUSIVE` | 数据抖动过大 | 先修测量，不算结论 |

`ROLLBACK_ON_TARGET` 这一档是真实项目里最常见的坑：**本地 x86 通过不代表目标平台通过**。
公开项目 `Parrotools/kunpengS2` 就栽在这里——8 输出 SIMD 本地 PASS，到鲲鹏上 Case1 精度失败。

## 6. 回滚规则

- 任一实验 `REJECT`，用 `git revert` 或回到上一 tag，**不要**手工删代码
- 保留失败分支（打 tag `E##-rejected`），因为面试时它比成功版本更有说服力
- 默认分支永远保持「四案全 PASS」的状态，不允许带病前进

## 7. 版本与提交约定

```
src/conv2d_v0.c   baseline，永不修改
src/conv2d_v1.c   E01 产物
src/conv2d_v2.c   E02 产物
...
src/conv2d_final.c 最终选定版本（可能是 v2，也可能回退到 v1）
```

每个 `vN` 的文件头注释必须包含：

```c
/* E## <标题>
 * 相对 v(N-1)：<一句话>
 * 假设：<...>
 * 结果：四案 PASS，median +X%（<平台>）
 * 代价：<...>
 */
```

这样即使只看代码，也能还原决策过程。
