# 面试讲法

## 主线：讲过程，不讲数字

面试官评估性能岗位，真正想确认的是四件事：

1. 你会不会**测量**（而不是凭感觉）
2. 你会不会**定位**（而不是穷举试错）
3. 你会不会**判断**（知道什么时候停、什么时候不值得做）
4. 你说的话**是否可信**（数据和结论对得上）

所以叙事重心应该是「假设 → 实验 → 判决」，而不是「我优化了多少倍」。
下面三个长度版本，都围绕这条主线。

## 一句话版本

> 我把一个 30 行的朴素四重循环卷积，在本地 x86 参考环境上做到基线 **×17~21.6**、
> 实测 **12.1 FLOP/cycle**；鲲鹏平台还没复测。
> 但比提速更值得讲的，是我定位到一个只读代码发现不了的问题：
> 改法在源码上完全等价，编译器却把乘加收缩成 FMA，精度直接超出 1e-5 容差。

## 2 分钟版本（讲价值，不讲细节）

- **问题**：FP32 二维有效卷积，4 组官方用例最大 6390×4256、核 81×81，单案 345 GFLOP
- **基线**：官方 30 行实现，四重循环 + `#pragma omp parallel for`，内层是 `output += input*kernel`
- **我做了什么**：局部累加器（+7.9~10.7%）→ 输出分块 4 路（×3.3）→
  输出维度向量化（×2.5）→ 向量宽度扫描（再 ×2.2~2.7）
- **第一次转折**：perf 显示 IPC 2.34 但每周期只有 1.9 FLOP，两个数对不上；
  读汇编发现 GCC 沿**归约维度**向量化，产生大量水平归约与 shuffle
- **第二次转折**：先把收益归因于「维度」，被 VB 扫描推翻——
  VB=4 崩到 12.8（根本没被向量化），VB=8→95，VB=32→209，VB=64→274。
  真实原因是三层：**宽度门槛 / 向量化维度 / 展开摊销**
- **同时证伪了六条**：`__restrict` −3%、8 路手工展开 −19.2%、2 行×4 列 −3%、
  行基址指针无收益、OpenMP 调度差异 <0.5%，以及我自己的单因归因
- **结果**：13.6 → 232~294 GFLOPS（×17~21.6），12.1 FLOP/cycle（x86，鲲鹏未测）
- **额外收获**：发现 FP32 归约顺序会直接影响 1e-5 容差，这是纯算法视角看不到的

## 10 分钟版本（讲设计，讲取舍）

按这条主线讲：

1. **先算 roofline**
   算术强度 ≈ 1615 FLOP/Byte → 纯 compute-bound → 优化重心是向量宽度和 ILP，不是减少访存
2. **再定位基线问题**
   `output += ` 是 read-modify-write；裸指针阻碍别名分析；`memset` 冗余
3. **逐层优化 + 每层验证**
   每层都跑四案对拍，误差保持 `0.0`
4. **用硬件计数器质疑已有的成功**
   45 GFLOPS 时我以为差不多了。perf 给出的 IPC 2.34 与「每周期 1.9 FLOP」互相矛盾，
   顺着这个矛盾读汇编，才发现编译器向量化错了维度。
   **一个已经跑通的优化，可能同时埋着更深的坑。**
5. **再做一次参数扫描，推翻自己的归因**
   我第一次把收益全归给「维度」，但 v3 是 4 路、v7 是 8 路，变量没隔离。
   补做 VB 扫描后：VB=4 崩到 12.8（根本没向量化）、VB=64 到 274。
   真实原因是三层，我一开始只讲了中间一层。
   **这一步是整条链上最有价值的部分——它证明我会证伪自己。**
6. **说清楚代价**
   - 分块让尾块处理变复杂（核尺寸都是奇数）
   - 8 路标量分块实测 −19.2%：寄存器压力顶不住，4 路是这个结构的甜点
   - 补充：公开项目记录过「8 输出 SIMD 在鲲鹏上 Case1 精度失败」，
     那是**别人的结果**，我只作为背景引用，没有复现
7. **诚实收尾**
   - 头部获奖方案用 SME 外积达到约一个数量级的更高吞吐，我没有走那条路
   - 我的价值在于完整的定位—验证—取舍链条，而不是绝对名次

## 高频追问与准备

| 追问 | 要点 |
|---|---|
| 为什么不用 im2col + GEMM？ | 大核（81×81）下 im2col 会把输入放大 KH·KW 倍（6561×），内存爆炸；小核才划算 |
| 为什么不用 FFT 卷积？ | 核大时理论有利，但 FP32 误差放大，1e-5 容差风险高；且需 padding/重叠相加，工程复杂度陡增 |
| 编译器为什么没自动向量化？ | RMW + 裸指针潜在别名；用 `-fopt-info-vec` 能看到 "possible dependence" 报告 |
| 线程加了为什么不线性加速？ | 我有实测曲线：T=1 9.42 / 2 18.51 / 4 28.95 / 6 36.25 / 8 42.76 / 12 37.20 GFLOPS。8 线程是拐点，12 线程掉 13%——超线程共享 L1/L2 反而互相拖累。单核效率只有约 37%，说明瓶颈在单核指令吞吐，不在线程数 |
| 你怎么知道瓶颈在计算不在访存？ | 算术强度 1615 ≫ roofline 拐点；且 perf 显示 IPC 高而非 stall 在 memory |
| 精度为什么会被 SIMD 影响？ | 归约顺序改变 → 浮点结合律不成立 → 误差累积路径不同。注意：沿**输出维度**向量化不改任何单条累加链，所以误差仍为 0 |
| 你怎么知道编译器向量化错了维度？ | perf 的 IPC 与 FLOP/cycle 对不上 → 读反汇编 → 看到 4 条 vmulps 后面跟一串 vunpcklps/vshufps/vextractf128。判断依据是「归约指令占比」，不是编译器报告 |
| 你怎么确认是维度而不是路数？ | 我一开始没确认，这是我的失误。补做 VB 单变量扫描后才发现：VB=4 根本没被向量化（汇编里 16 条 vaddss），VB≥8 才跨过 256-bit 门槛。所以是「宽度 + 维度 + 展开」三层共同作用 |
| 换到 x86 还成立吗？ | 方法论成立，向量宽度（AVX2 8×FP32）和缓存层级不同，需重新调 tile |

## 红线

- **不要**说"我复现了获奖方案"——那是别人的 SME 汇编
- **不要**把 x86 数据说成鲲鹏数据
- **不要**在没有实测时给具体加速比
- 提及公开作品时，明确说「我调研过」，而不是「我做过」

## 和另一段经历的配合

| 项目 | 证明什么 | 追问方向 |
|---|---|---|
| 工作经历（BWA/GATK 类） | 真实系统里的工程判断力 | 约束、取舍、团队分工、结果如何衡量 |
| 本项目（CONV） | 单点技术深度与量化能力 | 瓶颈定位、为什么选这个方案、数据怎么测 |

两者不能互相替代：一个证明「在约束下做对选择」，一个证明「能把性能压到极限」。

## 方法论专项：如果面试官问「你怎么做性能优化」

这是最能拉开差距的一问。建议按这个结构回答（约 60 秒）：

> 我一般分四步。
> **第一，先算，再动手。** 算算术强度和 roofline，判断是 compute-bound 还是 memory-bound，
> 这一步能砍掉一半无效方向。我做的这个卷积算术强度约 1615 FLOP/Byte，是纯计算瓶颈，
> 所以「减少访存」的天花板很低，力气应该放在指令级并行上。
> **第二，建立可信测量。** 至少三次重复，报 min/median/max；抖动大于收益就不下结论。
> **第三，把每个改动写成可证伪的假设**，先写证伪条件再写代码。
> 比如「输出 RMW 阻碍寄存器提升」这个假设，证伪条件是「汇编里输出访存仍在」。
> **第四，记录代价。** 每个优化都有代价——精度余量、复杂度、可移植性。
> 没有代价记录的优化，通常是抄来的。

如果被追问「举个例子」，给两个：

1. **E05：编译器报告不等于编译器做到了。** 我加 `__restrict` 后 GCC 报告
   「loop vectorized using 32 byte vectors」，听起来是好事，实测反而慢 3%。
   查汇编发现 `vaddps = 0` —— 归约那条链根本没被向量化，报告的是它尝试了什么。
2. **E02：主动设计一个预期失败的对照实验。** 行基址指针替代二维下标，
   直觉上应该更快，结果落在噪声带内（详见 `docs/experiments/E02-row-pointer.md`）。
   这个现象公开项目也报告过，我独立复现了一遍，用来校准自己的判断，
   不是「我发明了这个实验」。

这两个例子都指向同一件事：**凭直觉猜优化点，是这条路上最常见的错误。**

## 如何体现「知道什么时候停」

面试官常问「你最后为什么停在这里」。好的回答不是「因为没时间了」，而是：

> 有三条止损线：收益小于噪声、精度逼近门限、复杂度收益比失衡。
> 我停在 X，是因为再往下需要 Y，而 Y 带来的收益在测量噪声以内，
> 同时会把精度余量从 A 压到 B，风险不划算。这个判断本身也是优化能力的一部分。

## 边界声明（必须主动说）

- 数据来自哪个平台，必须说清；x86 数据不能说成鲲鹏数据
- 调研过公开获奖实现，不等于做过；提及时应说「我调研过」
- 未实测的推断要标明是推断
